What was wrong, and what I changed

The original app kept returning "Placed" even for weak inputs. I traced it to three concrete bugs rather than a bad model idea — the maths was fine, the setup around it was not.

Bug 1 — The form pre-filled every box with the dataset average.

Numeric fields defaulted to the cohort mean (CGPA 6.92, attendance 70.2%, aptitude 69.4, 3.5 projects, 3.6 certifications). That is already a placed-looking student. If you lowered CGPA but left the other nine fields untouched, the model still saw a strong profile and answered "Placed" — correctly, given what it was actually fed. Fix: every field now starts at the low end of its real range, so the prediction reflects what you type. Three one-click presets (Weak / Average / Strong) let you sanity-check the model in a second.

Bug 2 — Individual skill checkboxes carried almost no signal.

In this dataset, ticking any single skill moves the placement rate only from roughly 74% to 84%. What actually matters is how many skills a student has: 1 skill → 51.9% placed, 4 skills → 93.7%, 6 skills → 98.8%. The old feature set never encoded that count, so the skills section barely moved the answer. Fix: skill count is now an explicit model feature, and it is one of the strongest predictors in the trained model.

Bug 3 — Gender was a dead feature.

Categorical yes/no fields were encoded with a test for "yes/true/1". Gender values ("Male", "Female", "X") match none of those, so every student encoded as 0 and the column contributed nothing. Fix: Gender is excluded from the model entirely — which is also the right call for a placement tool, since predicting on gender is both weakly informative here and ethically inappropriate.

More programming languages

You asked for more languages, since companies look for far more than the nine in the dataset. The form now offers — skills across five categories: programming languages, CS fundamentals, data/AI, cloud/DevOps, and web/mobile.

How the extra languages are scored — stated honestly. Nine skills appear in the dataset () and have their own individually-trained coefficients; they are marked with a ★ in the form. The other — (TypeScript, Go, Rust, AWS, Docker, React and so on) do not appear anywhere in the 1,000 student records, so no honest per-skill weight can be learned for them. They count toward your skill count, which is a genuinely data-backed predictor. I could have invented per-language weights to make the demo look richer, but those numbers would be fiction, so I didn't.

On "perfect accurate prediction"

No model is ever 100% right, and any dashboard claiming that is lying to you. What I can promise is that this one is correct and consistent: weak inputs give a low probability, strong inputs give a high one, and every metric shown is measured, not typed in. On held-out data it scores — accuracy and — ROC-AUC, with 5-fold cross-validation at —. It gets 8 of the 200 test students wrong, and the Model Performance tab shows exactly which way those errors fall.

One caveat worth knowing before a demo: this dataset separates very cleanly, so probabilities cluster near 0% or 100% rather than spreading evenly. That is a property of the data, not a bug — real placement data is messier and would produce softer probabilities.
